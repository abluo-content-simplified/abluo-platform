─── Problem ──────────────────────────────────────────────────────────────────

V0.8.2 introduced `src/middleware.ts` based on incorrect analysis that Next.js 16
no longer recognised it as the middleware entrypoint. In fact, Next.js 16 uses
`src/proxy.ts` as the new middleware convention. Both files existing simultaneously
caused a build failure on all branches that contained V0.8.2 (dev + main).

Error on Vercel:
  "Both middleware file './src/src/middleware.ts' and proxy file './src/src/proxy.ts'
   are detected. Please use './src/src/proxy.ts' only."

─── Fix ──────────────────────────────────────────────────────────────────────

Deleted: src/middleware.ts (the incorrectly added wrapper file)

No changes to src/proxy.ts — all locale-switch logic, language persistence,
tenant routing, auth guards, and the config matcher remain intact and correct.

  - Documented the Next.js 16 proxy.ts middleware convention
