### Admin read (what Tom gets)
`is_abluo_admin()` is true only when the signed JWT has `aal = 'aal2'` (an
MFA-verified session) AND carries `platform_role = abluo_admin` either
top-level (auth hook, 006) or in `app_metadata` — so the flag works even if
the hook isn't wired in Auth → Hooks, but never on a password-only session.
Your user needs `app_metadata.platform_role = "abluo_admin"` (already what
`src/proxy.ts` checks). Read-only: no write policy uses it.

## 4. End state 028 enforces

- RLS on every `public` table. anon/PUBLIC: no privilege on any relation.
- authenticated: SELECT on the 9 app tables; UPDATE only `profiles.full_name`
  and `form_submissions.status`; no INSERT/DELETE anywhere. All writes go via
  server routes using service role (verified in `src/lib/forms/submissions.ts`,
  `notifications/consumer.ts`, `translate/usage.ts`).
- Project grain via `get_my_project_ids()` / `get_my_writable_project_ids()` on
  form_submissions, form_events, translation_usage, inquiries (legacy
  null-project inquiries: tenant owners only). Changes vs before: tenant
  editors/viewers without a project grant no longer see inquiries (nothing in
  `src/` reads inquiries); dead owner write policies on projects /
  tenant_members / project_members removed (no grant ever backed them).
- EXECUTE revoked from anon/PUBLIC on all helpers, the hook, trigger functions
  and the usage total. Default privileges: future tables are not granted to
  anon/authenticated.

## 5. Rollback

028 removes access only; no data is touched. To return to exactly the
pre-028 grants and policies, in the SQL editor:

```sql
begin;
do $$ declare r record; begin
  for r in select tablename, policyname from pg_policies where schemaname = 'public' loop
    execute format('drop policy %I on public.%I', r.policyname, r.tablename);
  end loop;
end $$;
-- paste the rollback_sql cell saved in step 1 here
commit;
```

Proven locally: `cd supabase/verify && node rollback-028-proof.mjs`.
Optional leftovers: `drop function if exists public.is_abluo_admin();` and
`alter default privileges in schema public grant all on tables to anon, authenticated;`
(only if you want Supabase's old default back — not recommended).
