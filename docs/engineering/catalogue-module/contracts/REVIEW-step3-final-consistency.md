## (C) Inconsistencies — location and exact fix

### Must fix before "Accepted" (C-1 … C-8)

**C-1 Audit kind regex rejects `public_name.migrated`.** [C] §12.2 SQL `check (kind ~ '^[a-z]+(\.[a-z_]+){1,2}$')`: the first segment allows no underscore, so `public_name.migrated` (the K-2 audit row, D-12) fails the CHECK and every D4 audit insert is refused. A-12 and A-19 would both fail. (The step-2 review's C-21 missed this; I-24(b) noticed the regex shapes names but not this case.)
*Fix:* replace the regex in §12.2 (SQL comment and CHECK) and in A-19 with `'^[a-z]+(_[a-z]+)*(\.[a-z]+(_[a-z]+)*){1,2}$'`, and add to A-18: "`public_name.migrated` and every other `CatalogueAuditKind` literal pass the SQL CHECK (test runs the regex over the union)".

**C-2 Readiness consumes an instant-based type while being declared instant-free.** [C] §6.2 `FormatReadinessFacts.availability: AvailabilityExplanation` ("C5 explainAvailability(...) … unchanged") and §6.3 semantics 2 ("a format whose `availability.state === 'unavailable'` produces no price finding"), §6.14 (`explainAvailability(...)`, `availableAtAnyTime(explanation)`), fixtures R-08/R-09/R-12 — but `AvailabilityExplanation` requires `at` and `timeZone` ([A] C5-2), and D-6 / [C] "Time-based availability is not a readiness problem" says readiness takes no instant. [A] Interfaces table already says C6 uses `EffectiveRule` (instant-free). Semantics 2 also contradicts rule 15 (`everAvailable`).
*Fix ([C]):* §6.2 → `availability: EffectiveRule // C5 effectiveRule(...) for that offering context — instant-free; issues carry availability.* codes`; `everAvailable` → "`availableSometime(availability.rule)` (C5a)"; `priceCoverage` comment → "`priceCoverage(format, oc, channels, weekProfile(availability.rule))`". §6.3 semantics 2 → "A format with `everAvailable === false` produces no price finding; `everAvailable === true` and no price ⇒ finding; the item stays available." Semantics 7 → "…does some price apply at every minute of the week **at which the format is available** in this context". §6.14 → `effectiveRule(...): EffectiveRule`, `availableSometime(rule)`, `weekProfile(rule)`, `priceCoverage(format, oc, channels, availability: WeekProfile)`. R-08/R-09/R-12: replace "`AvailabilityExplanation.state:'available'/'unavailable'`" by "`everAvailable: true/false`". For the generalised `general` context, C5 must expose `effectiveRule` for `general` too: [A] C5-4 add "`effectiveRule(..., ctx: OfferingContext)`; for `general` with channels the result is the any-channel union profile (source `anyChannel`)" — `availabilityMatrix` already keys `'general'`, so this is one signature change.
