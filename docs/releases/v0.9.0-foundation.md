## 1. Platform Capabilities

### Multi-Tenant Architecture
- Single Next.js 16 codebase serves multiple client websites
- Tenant routing via subdomain (`livener.preview.abluo.app`) and path-based dev routing (`dev.abluo.app/livener`)
- `projectSlug` is the universal tenant key across all Sanity content — every GROQ query filters by it
- `proxy.ts` handles all routing logic (Next.js 16 middleware entrypoint — never `middleware.ts`)

### Content Management (Sanity)
- **Routable document types:** `page`, `event`, `homePage`, `post` (schema done, no route yet)
- **Non-routable types:** `client`, `project`, `designSystem`, `siteConfig`, `mediaAsset`, `livePageType`, `eventsPageType`
- **Localized slugs** (`localizedSlug`) on all routable types with `redirectFrom` for slug migrations
- **Localized content fields:** `localizedString`, `localizedText`, `localizedPortableText`
- **Content localization** (per-tenant, Sanity) is separate from **interface localization** (platform-wide, next-intl)
- Sanity Studio served at `/studio` — platform admin only, never exposed to clients

### Design System
- Full inheritance chain: `Abluo Base (template)` → `Tenant DS (active, projectSlug-scoped)`
- `DS_FIELDS_SELECTION` GROQ projection is the single source of truth for all DS fields
- `resolveDesignSystemInheritance()` walks the parent chain (max depth 5); child overrides parent
- DS fields cover: typography, colors, surfaces (glass/solid/transparent), forms, navigation, cards, shadows, layout, logo height, motion tokens
- Motion token pipeline: Sanity → `buildCssVars()` → CSS variables → section components
- Export/Import actions in Studio (field-agnostic, strips only 5 Sanity metadata keys)

### Livener — Current Tenant Implementation
- **Homepage** at `/[locale]/livener`
- **Live page** at `/[locale]/livener/live` — `livePageType` Sanity document; Cloudflare Stream embed (`customer-aayaptcudal3r1fx`); featured events list
- **Events listing** at `/[locale]/livener/events` — `eventsPageType` Sanity document; hero image + video embed; 3/2/1 responsive grid; uniform card height
- **Event detail** at `/[locale]/livener/events/[slug]` — localized slug lookup, redirectFrom, SlugMapProvider, hreflang
- **Navigation** — `navLinks[]` with `linkType` (internal/external), `internalPage` (homepage/live/events), `externalUrl`

### Dashboard (Admin)
- Available at `admin.abluo.app` (production) or `localhost:3000/en/dashboard`
- Sections: Dashboard, Posts, Content, Media, Leads, Projects, Settings
- **Media library** at `/en/media` — upload via `POST /api/media`, list via `GET /api/media`
- Supabase authentication with role-based access (`admin` / `client`)
- Platform admin (Tom) has full Sanity Studio access; clients get the minimal dashboard only

### Deployment Badge
- Shown on DEV and PREVIEW only, never on Production
- Pill: `ENV • commitSha`
- Expanded: Environment, Commit, Branch, Built
- All values baked in at build time via `next.config.ts` → `NEXT_PUBLIC_*` env vars

## 3. Database Architecture (Supabase)

**Project ID:** xsdamzirepfqlutvqfbe

### Tables

#### `public.tenants`
One row per client account. Mirrors the Sanity `client` document.
```
id           uuid PK
slug         text UNIQUE        -- e.g. 'livener'
display_name text
domain       text UNIQUE        -- e.g. 'livener.net'
status       text               -- 'active' | 'inactive' | 'draft'
plan         text               -- 'starter' | 'pro' | 'enterprise'
created_at   timestamptz
```

#### `public.profiles`
Links a Supabase auth user to a tenant and role. Auto-created on signup via `handle_new_user()` trigger when `tenant_id` is present in user metadata.
```
id          uuid PK → auth.users.id
tenant_id   uuid → tenants.id
role        text               -- 'admin' | 'client'
full_name   text
created_at  timestamptz
```

#### `public.leads`
Contact form submissions. Tenant-scoped.
```
id          uuid PK
tenant_id   uuid → tenants.id
name        text
email       text
message     text
source      text
status      text               -- 'new' | 'read' | 'archived'
lead_status text               -- 'new' | 'contacted' | 'qualified' | 'converted' | 'closed' | 'spam'
created_at  timestamptz
```

#### `public.projects`
One row per deployable website. A tenant can own multiple projects.
```
id             uuid PK
slug           text UNIQUE      -- matches Sanity projectSlug
tenant_id      uuid → tenants.id
name           text
custom_domain  text UNIQUE      -- set when client goes live
default_locale text             -- e.g. 'it'
status         text             -- 'draft' | 'preview' | 'active' | 'inactive'
created_at     timestamptz
```
Preview URL pattern: `{slug}.preview.abluo.app`

### Row Level Security
All tables have RLS enabled. Users are scoped to their own `tenant_id` derived from `profiles`. Admins can manage their tenant's projects.

## 5. Tenant / Project Model

```
client (Sanity)                    tenant (Supabase)
  └── tenantSlug ←──────────────── slug
        └── project (Sanity)       project (Supabase)
              └── projectSlug ←─── slug
                    ├── designSystem
                    ├── siteConfig
                    ├── homePage
                    ├── livePageType
                    ├── eventsPageType
                    ├── page[]
                    ├── event[]
                    └── post[]
```

- `client.tenantSlug` drives URL routing and subdomain resolution
- `project.projectSlug` is the universal content key — every Sanity query filters by it
- Design system inherits from a platform template via `parentDesignSystem`
- `siteConfig` holds navigation, footer, locale settings, SEO defaults
- `livePageType` and `eventsPageType` are singleton documents per project (one per `projectSlug`)

## 6. Authentication Model

### Current Implementation
- **Provider:** Supabase Auth (email + password)
- **Session management:** Supabase SSR client with cookie-based sessions
- **Role enforcement:** `proxy.ts` reads Supabase session on every request to `admin.abluo.app`; role `admin` required for admin-only routes
- **Profile auto-creation:** `handle_new_user()` trigger inserts a `profiles` row when `tenant_id` is present in signup metadata
- **JWT custom claim:** `user_role` decoded in `proxy.ts` to enforce admin-only route access

### What Is NOT Implemented Yet
- Client self-signup flow (clients are currently created manually in Supabase dashboard)
- `tenant_members` table (planned — the next migration after this checkpoint)
- Invitation-based onboarding
- Password reset flow in the platform UI
- Multi-user per tenant with different roles

### Database rollback
The database is **not** modified by this release. If a future migration breaks something:

1. In Supabase dashboard → SQL Editor, run the inverse `DROP`/`ALTER` statement for the migration
2. Migrations are in `supabase/migrations/` — each file is self-contained
3. At the time of this tag, the applied migrations are:
   - `schema.sql` (base)
   - `001_leads_add_lead_status.sql`
   - `002_projects.sql`
4. No migration tools (Flyway, Liquibase, Supabase CLI migrations) are in use — migrations are applied manually in the Supabase SQL editor

### Sanity rollback
Sanity content is not versioned with this tag. Sanity has its own history per document. If a schema change causes issues, revert the schema in `src/lib/sanity/schema.ts` and redeploy.
